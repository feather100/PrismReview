## 三、必须修正的问题（P0，重新调研时逐条回应）

### 3.1 结论 1 必须收窄并补充检索维度

**现状：** "目前没有任何产品将……组合起来，用于通用商业文档/方案/架构评审。这是一个空白市场。"

**问题：**
- 附录 B 的搜索关键词全部面向开源/学术（`multi-agent debate LLM`、`LLM peer review multi-agent` 等），**没有覆盖商业软件与平台侧**；
- 对主打通用商业文档评审的产品而言，竞争格局应包括：办公套件 AI（Notion AI、飞书/钉钉/语雀、Confluence + Atlassian Intelligence）、企业"智能评审/智能审批"平台、GPT Store / Dify 模板市场中的"方案评审"类应用、以及通用 LLM 应用（ChatGPT/Claude/通义/Kimi 长文档 + 定制 Prompt 的直接替代场景）；
- "0 竞品"同样可能意味着"0 被验证的需求"（Tier 1 项目 star 普遍 < 100）。蓝海与死海在数据上无法区分，不能仅凭检索结果断言市场存在。

**重新调研要求：**
- 结论 1 修改为限定句："**在开源/学术检索范围内**未发现直接竞品；商业 SaaS 与办公套件侧需另行一轮桌面调研后再下结论"；
- 新增一节"商业与平台侧竞争扫描"，覆盖上述四类对象，并给出"最可能进入该品类的 3–5 个主体 + 进入路径 + 时间窗估计"；
- 新增一节"需求侧证据"：列出支持"市场存在"的外部证据（论文引用量、企业 LLM 评审需求、相关产品的用户反馈/定价信号），若无证据则如实说明。

### 3.2 必须新增"评分可信度验证"工作流

**现状：** 加权多维评分被定位为最大差异化，但全文只引用了 agentic-paper-review 的 Spearman ρ=0.74 和 AssessmentAI 的 AI+人工对比模式，**未将其转化为 PrismReview 自己的验证计划**；阶段 3"评分算法的打磨"没有可验收标准。

**问题：** 企业 CTO/PMO 用 LLM 分数做决策的第一问题是"分数凭什么可信"。没有可信度验证，加权评分只是装饰性数字。

**重新调研要求：**
- 在行动方案中新增"评分质量基准"工作流，明确：选取 10–20 份真实方案文档 + 人工专家评分作为 gold standard；定义一致性指标（相关性、分布校准、置信区间）；明确"通过"阈值；
- 调研内容补充：如何从 agentic-paper-review / AssessmentAI / Eureka 的方法中提取可复用的验证协议；
- 输出：一页"评分可信度验证方案"作为阶段 3 的前置交付物。

### 3.3 自研状态机 vs 编排框架的口径必须统一

**现状：** 结论 4 说"编排层有大量成熟开源轮子可复用，不需要从零自研状态机引擎"；但 README 的承重决策是**自研 9 值状态机**（显式 `route*` 方法、非通用图遍历、53 项单测覆盖），理由是**可审计性、可测试性、Moderator 中心化**。

**问题：**
- 文档与产品决策自相矛盾，读者无法判断哪边是"最终结论"；
- 更关键：LangGraph 是 Python、Semantic Kernel 偏 .NET，而 PrismReview 是 NestJS/TypeScript 栈。"复用轮子"在此场景 = "用另一种语言重写一遍"，成熟度红利不会跨语言转移，结论 4 的"不需要自研"不成立。

**重新调研要求：**
- 9.2 改为"借鉴其**模式**（checkpoint 持久化、interrupt 语义、条件边），而非更换实现"；
- 阶段 2 评估目标明确为"**证明或放弃**"：不预设迁移，评估项必须补充"语言边界成本、可审计性损失、依赖重量、迁移工作量上限（建议 ≤ 3 天）"，并给出明确的决策门（Go / No-Go 条件）；
- 补充说明 Semantic Kernel（.NET）与当前技术栈的匹配度问题。

## 四、建议补充的内容（P1）

### 4.1 评审成本 / 延迟预算模型

- 多 persona × 多轮辩论的 token 成本会快速失控（参考 Lavern 67 个专家、10 轮验证循环的量级）；
- 调研应给出"评审一次的成本与时长估算"（按 1 份 50 页文档、N 角色、M 轮计算），并建议产品分层：**快速档（2 角色 × 1–2 轮）与深度档（6 角色 × 3 轮）**；
- 输出：一页"成本模型 + 分层策略"。

### 4.2 行动方案增加市场验证动作

- "空白市场"假设需要用户侧检验：选定"通用商业方案评审"楔子场景，访谈/试用 5–10 个目标用户（CTO 办公室 / PMO / 咨询公司）；
- 建议与阶段 1 考古并行，不串行。

### 4.3 补充关键文献

| 文献 | 补充理由 |
|------|---------|
| *Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena*（Zheng et al., 2023） | 评分校准与"LLM 当裁判"偏差（位置偏好、冗长偏好）的理论基础，直接支撑加权评分设计 |
| Anthropic *How we built our multi-agent research system*（工程博客） | 子代理并行 + 编排的工程实践，2025 年标杆 |
| *Generative Agents*（Park et al., 2023） | persona 与记忆（memory）设计，支撑蒸馏式 Memory 的借鉴来源 |

### 4.4 口径修正：执行摘要结论 3

- 7.1 矩阵显示 PR Council（Judge）、Doc-Review（分类评分）、manuscript（矩阵）、agentic-paper（维度）、AssessmentAI（权重）**均有评分能力**，结论 3"加权多维评分报告是最大差异化壁垒"与矩阵自相矛盾；
- 改为："**多 persona × 多轮辩论 × 加权评分 × 审计溯源的可组合能力**是最大差异化"，并保留 9.1 中"组合 + 企业级能力"的正确表述。
